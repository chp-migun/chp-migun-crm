# tools/ — בדיקת תוכנית אדריכלית לפני שמתחילים לסמן

כלים לקריאת DWG של אדריכל **בלי לפתוח אוטוקאד גרפי**, כדי לענות על
שלוש שאלות לפני שמסמנים ולו קליק אחד:

1. **באילו יחידות התוכנית באמת?** — לא לפי `INSUNITS` שבכותרת.
2. **איפה הממ"דים?**
3. **האם המידות שכתובות בתוכנית תואמות את הגאומטריה?**

## הצינור

```powershell
# 1. DWG → DXF  (accoreconsole, בלי GUI)
& 'C:\Program Files\Autodesk\AutoCAD 2021\accoreconsole.exe' `
    /i 'C:\migun\in\PLAN.dwg' /s 'C:\migun\repo\mamad-annex\tools\dwg-info.scr' /l en-US
```
`dwg-info.scr` מדפיס INSUNITS / EXTMIN / EXTMAX / מספר ישויות ושכבות,
ושומר `C:\migun\tmp\P-001.dxf`. שאר הכלים קוראים את ה-DXF הזה.

```bash
python analyze2.py      # פריסות, INSERT-ים, ויופורטים, בלוקים גדולים
python analyze3.py      # תוכנית קומה לכל בלוק + איתור ממ"דים בתוכה
python measure.py CX CY HALF          # עוביי קירות בפועל סביב נקודה
python floor_overview.py out.png X2   # קומה שלמה, ממ"דים מסומנים A/B/C/D
python zoom_mamad.py out.png CX CY HALF   # זום עם רשת 50 ס"מ
python render_win.py out.png [x0 y0 x1 y1]  # רינדור מלא (כולל הצללות)
```

## שתי מלכודות שכבר נתקלנו בהן

**`INSUNITS` משקר.** בתוכנית של גוטסמן (מבוא חצרות 2) הכותרת הכריזה
`INSUNITS=5` (מ"מ) והתוכנית בפועל בסנטימטרים. אם הכלי היה סומך על
הכותרת, הנספח היה יוצא פי 10 קטן. **קובעים יחידות לפי הגאומטריה:**
`measure.py` מוציא את עוביי הקירות בפועל — 11/15/20/30/35 זה ס"מ,
110/150/200 זה מ"מ.

**עברית ב-DXF מקודדת ב-`\U+XXXX`** (אותה שיטה שבה migun.lsp כותב).
חיפוש טקסט של "ממ\"ד" ייכשל בלי לפענח קודם. `analyze3.py` מפענח.
בנוסף, MTEXT מפצל מחרוזת לריצות עם קודי גופן (`\fArial|...;`) —
המילה "ממ\"ד" מגיעה כשלוש ריצות נפרדות, אז מחפשים מצע ("ממ") ולא
מחרוזת מלאה.
